---
title: "Goals"
description: "The single convergence/constraint abstraction — when an operator stops itself."
---

A `Goal` is the only abstraction ADR uses for stopping. The operator evaluates all active goals
every cycle and stops *autonomously* when **all** of them are satisfied — no counter expiry, no
human signal, no external monitor.

## The Goal

```python
Goal(name="mse",        metric="model_mse",   threshold=0.005, direction="minimize")
Goal(name="gap",        metric="band_gap_ev", threshold=1.5,   direction="maximize")
Goal(name="cpu_health", metric="cpu_percent", threshold=90.0,  direction="minimize")
```

| Field | Meaning |
|---|---|
| `name` | Identity. A runtime goal with the same `name` upserts in place. |
| `metric` | The key looked up in the observation dict. |
| `threshold` | The boundary value. |
| `direction` | `"minimize"` → satisfied when `value < threshold`; `"maximize"` → `value > threshold`. |
| `inclusive` | `True` flips to `<=` / `>=` so a discrete goal like "reach 5 hits" fires at exactly 5. Defaults to `False` (strict). |

## How satisfaction is checked

`satisfied(obs, snapshot)` looks up the metric in this order:

1. `obs[metric]` — primary: what `@observe` explicitly returned.
2. `snapshot.objectives[metric]` — fallback: operator state (e.g. `radius`, `center`).

<Note>
**`snapshot.runtime` is never checked automatically.** Resource or telemetry metrics must be
surfaced explicitly in `@observe`. If a metric is found in neither place, the goal returns `False`
and warns once. This is the rule behind [resource-aware steering](/guides/resource-aware-steering).
</Note>

## Source-agnostic by design

`Goal` does not care where a metric comes from — a task result, operator state, a GPU-utilization
subscription. That is determined entirely by what `@observe` puts into `obs`. The same `Goal` type
expresses a scientific convergence criterion and a hardware constraint side by side.

## Multi-goal AND convergence

There is no special multi-objective API — just more entries in the list. The operator does not stop
until **every** goal is satisfied simultaneously:

```python
@goals
def criteria(self):
    return [
        Goal(name="hits_found",   metric="n_hits",        threshold=5,    direction="maximize"),
        Goal(name="under_budget", metric="compute_hours", threshold=200,  direction="minimize"),
        Goal(name="cpu_healthy",  metric="cpu_percent",   threshold=90.0, direction="minimize"),
    ]
```

## Static vs runtime goals

- **Static goals** are returned by `@goals` at class level.
- **Runtime goals** are proposed by a policy via `Decision(goals=[...])`. Same `name` upserts;
  a new `name` adds an independent requirement; `Decision(remove_goals=["name"])` removes one.

Both kinds are evaluated together every cycle. The convergence check fires after DECIDE:

```python
all_goals = static_goals + runtime_goals
if all_goals and all(g.satisfied(obs, snapshot) for g in all_goals):
    decision.stop = True
```
