## `Snapshot`

A frozen Pydantic model handed to `@observe` each cycle. Safe to log, serialize, or pass across
coroutines.

| Field | Lifetime | Contents |
|---|---|---|
| `observations` | cleared each cycle | `result.{uid}`, `error.{uid}`, `child:{id}:{k}` |
| `runtime` | persists | `uid → PENDING/RUNNING/DONE/FAILED/CANCELED` |
| `objectives` | persists | annotated attrs, policy params, mirrored child state |
| `artifacts` | persists | stable ids, file paths |
| `directives` | cleared each cycle | instructions from a parent |
| `task_context` | persists | `uid → {name, kwargs}` |
| `cycle` | — | current cycle index |

**Task error shape** — `observations["error.{uid}"]` is `{"task_name": str, "message": str, "type": str}`.

## `RuntimeState`

The mutable backing store the operator owns. `Snapshot` is its frozen view. Live references not in
the snapshot: `task_futures: dict[str, Future]` and `history: deque[Snapshot]` (maxlen 64). User
code reads state through `Snapshot` and writes it through attribute assignment or `UPDATE_PARAM` —
not directly.

## Messaging

The inbox (`asyncio.Queue`) is the only input channel.

### `MessageKind`

| Kind | Direction | Payload |
|---|---|---|
| `TASK_EVENT` | backend/local → operator | `{uid, state, result/error}` |
| `SNAPSHOT` | child → parent | child `Snapshot` |
| `DIRECTIVE` | parent → child | `{directives: dict}` |
| `CUSTOM` | parent / MCP → operator | arbitrary mutation |
| `STOP` | system → operator | `None` |

### `InboxMessage`

The envelope placed on the inbox: `kind` (`MessageKind`), `sender_id`, `payload`.

### `MessageBus`

Routing helper for inter-operator messaging.

## Observers

### `ObserverBase`

Protocol with three synchronous hooks:

```python
def on_start(self, operator_id: str, metadata: dict) -> None: ...
def on_cycle(self, snapshot: Snapshot, obs: dict, decision: Decision) -> None: ...
def on_stop(self, final: Snapshot | None, reason: str) -> None: ...
```

Attach via `Operator(..., observer=...)`. Observers are a side channel — they never feed back into
state. See [Logging & observability](/guides/logging-and-observability).

### `RecordingObserver`

```python
RecordingObserver(path)   # captures per-cycle obs (+ decision) to JSONL
```

### `replay_trace`

```python
decisions = await replay_trace(path, candidate_policy, operators=None)
```

Re-drives a different policy against a recorded `obs` sequence — offline, open-loop (reads only the
recorded `obs`). `operators={name: OperatorClass}` (optional) back-fills `operator_cls` on
`SPAWN_OPERATOR` decisions so hierarchical policies replay cleanly. See
[Record & replay](/guides/record-and-replay).

## Logging

### `enable_logging`

```python
enable_logging(
    level=logging.INFO,
    *,
    output_file=None,      # also write to this file (ANSI colors stripped)
    file_level=None,       # defaults to `level`
    use_colors=True,       # color the level name on a TTY console
    show_details=False,    # add process/thread info per line
    stream=None,           # default sys.stderr
    configure_stack=False, # also configure AsyncFlow + RHAPSODY at the same level
) -> logging.Logger
```

Configures the `radical.adr` namespace logger for user-facing INFO/DEBUG narration of the
Observe → Decide → Act loop. Sets `propagate=False` so ADR logs are never duplicated and survive a
sibling reconfiguring the root logger. Uses the same pipe-delimited format as AsyncFlow and RHAPSODY.
See [Logging & observability](/guides/logging-and-observability). Logging is a side channel — it never
flows through `state`, `snapshot`, or `@observe`.
