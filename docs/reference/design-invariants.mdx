These invariants are the contract behind every page in these docs. If something surprises you,
check it against this list first.

## The sacred boundary

The Operator **only Observes, Decides, and Acts.** It never owns scheduling, execution lifecycle, or
distributed resources. AsyncFlow owns workflow execution; RHAPSODY / RADICAL-Pilot own task
execution. Even `spawn_operator` / `cancel_operator` / `cancel_task` are *steering* — they delegate
to `child.start(*futures)` and `future.cancel()`. See
[Mental model](/get-started/mental-model#the-sacred-boundary).

## Mandatory decorators

- **`@observe` is mandatory.** `run()` raises `TypeError` before the first cycle if undefined. No
  default observation exists.
- **`@decide` is mandatory.** An empty `Policy` raises `PolicyError` on first call — no silent
  empty-`Decision` fallthrough.

## Execution model

- **`@act` runs in the event loop** with `self` available, and chooses its own execution strategy:
  local computation, `engine.function_task`, or `engine.block`. The operator never pre-registers
  tasks — registration happens at invocation time.
- **Action application is execution-agnostic.** The operator calls the `@act` method, inspects the
  return (Future or plain value), and routes accordingly. One path for all execution modes.
- **One-cycle latency.** A task dispatched in cycle N produces a result visible in cycle N+1 —
  async tasks and local acts alike.

## Input and state

- **The inbox is the only input channel.** Task completions, local results, child snapshots, parent
  directives, MCP mutations — all arrive through the inbox and are drained each cycle. No
  out-of-band state mutations.
- **State proxying is transparent.** `self.radius = 2.5` writes `state.objectives["radius"]`, visible
  in `snapshot.objectives` and readable in `@observe`. No serialization step.
- **Terminal task handles are released.** Once a task settles, the operator stops holding its live
  Future and keeps only its result in a bounded cache, so long runs stay memory-bounded. A
  `depends_on` on a settled task still resolves; the cache window is large enough that realistic DAGs
  are never affected.
- **Checkpoints persist steering state only.** `save_checkpoint`/`load_checkpoint` serialize cycle,
  objectives, runtime statuses, `task_context`, runtime goals, goal streaks, and child lifecycle
  metadata — never live `Future`s (those belong to AsyncFlow/RHAPSODY). In-flight tasks are recorded
  as `LOST` for the resumed policy to `retry_task`.

## Goals

- **Goals check before act.** The goal check runs after DECIDE, before ACT. The stop cycle's actions
  still apply.
- **Goals are source-agnostic and explicit.** `satisfied` reads `obs[metric]` then
  `snapshot.objectives[metric]`; `snapshot.runtime` is never auto-checked. Resource metrics must be
  surfaced through `@observe`.

## Children

- **Child operators are first-class.** Declared with `add_child`, launched with `SPAWN_OPERATOR`,
  observed through `self.child(name)` → a read-only `ChildHandle`. `Future`, `UID`, `artifacts`, and
  `child:*` string keys are internal — they never appear in policy or operator code. Names, count,
  config, and dependencies are all runtime values.
- **SNAPSHOT propagates all child state.** A child's observations mirror into the parent's per-cycle
  `observations`; its runtime and objectives mirror into the parent's **persistent** `objectives`
  (latest-wins), so the latest child metrics survive across parent cycles even when a child's final
  SNAPSHOT and its block-Future `DONE` land on different cycles.
- **Child lifecycle is runtime-owned, declarative.** `spawn_operator` is idempotent ("ensure
  launched") — a re-emit on an already-started child (incl. terminal states) is a no-op + a logged
  warning; there is no user-managed spawn-once flag. `restart_operator(name)` re-runs from the
  **initial** config; `cancel_operator(name)` leaves a `CANCELED` tombstone. All three are steering
  verbs.
